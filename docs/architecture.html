Time to Safety: how the system is built

A flash-flood warning planner for Nepal's mountain valleys. From a single report that a river has burst, it computes who still has time to walk uphill to safety, ranks who to warn first, and tells a resident on the riverbank which way to go. Everything runs in one container on an IBM z17 in LinuxONE Community Cloud.

1 · The core loop

The question we answer is not "will a flood happen" (nobody can predict a landslide-dam burst) but "once it has started, who has time to run?". Each step below is a separate module, and each produces a number a person can check.

Why slack, not risk

On Oct 11 the walk to safe ground from Jagat, Salleri or Soti was only 1–3 minutes. What decided who was safe was when the warning went out. Slack makes that visible: with the villagers' phone relay at 03:30, nobody in the footprint is short of time; with the official SMS at 06:40, all ~1,456 people are. The planner shows both, side by side.

2 · Deployment on LinuxONE

One Docker image, built on the VM itself. The API binds to localhost, so the only way in is an SSH tunnel: no web port is open to the internet. Terrain data is a mounted volume, so the image stays small and the same image serves both valleys.

4 · What happens per request

The expensive work happens once per valley and once per flood scenario. After that, every question a person asks is answered from memory in milliseconds.

5 · The resident Go page

Built for someone who is frightened and has a phone in one hand. No setup and almost no buttons: it finds you, says one thing in big letters, counts down, points, and keeps working when the network drops.

7 · LinuxONE and AI

What running on IBM Z changed in practice, and what we measured on the Telum on-chip AI accelerator (NNPA). Full numbers: docs/linuxone-ai.md.

  • Built where it runs. Terrain rasters, model pickles and the compiled C search are all produced on the VM itself, so nothing is cross-built on a laptop.
  • No pip wheels for the scientific stack on s390x. numpy, scipy, scikit-learn and rasterio come from Ubuntu's s390x packages; only FastAPI and Uvicorn come from pip.
  • One machine, many agents. Each teammate's agent tests on its own port (8001–8003), and a new image is swapped into 8000 only after it passes, with the previous tag kept for rollback.
  • Privacy. No reporter identities are stored, the API is never exposed publicly, and nothing leaves the machine.

9 · Limits

  • The flood is an envelope (arrival and height along the river), not a hydrodynamic simulation. Bands are wide on purpose and the planner uses the early edge.
  • Wave speed calibrated on Oct 11 does not transfer to Aug 26 (up to 163 minutes late), so each valley uses its own real flood.
  • Two lost bridges on Oct 11 (Soti, Arughat) are missed: the D8 channel sits up to 175 m from the real river at Arughat.
  • People per building (4) and 5 minutes to spread a warning are assumptions, stated in the UI.
  • Triggers are entered by a person; live DHM/BIPAD feeds are not wired in. Mesh relay between phones is planned, not built.
